# Phase 1 成果物: 規制・法務確認質問票（11-regulatory-questions）

## Goal
法務責任者・外部専門家への確認を漏れなく実施するため、判断質問を固定化する。

## Context
運用形態により、登録・契約・AML/CFTの要求が変わる。

## Constraints
- Yes/Noで終わらず、根拠資料と責任者を必ず記録する。
- 回答不能項目は `外部承認が必要` のまま残す。

## 質問票
| ID | 質問 | 期待する回答形式 | 状態 |
|---|---|---|---|
| RQ-01 | 本運用は Model A/B/C のどれか | A/B/C + 根拠 | 外部承認が必要 |
| RQ-02 | 自社は電子決済手段等取引業・電子決済等取扱業の登録対象か | 要/不要 + 根拠法令 | 外部承認が必要 |
| RQ-03 | 加盟店審査・契約が必要か | 必須/不要 + 条件 | 外部承認が必要 |
| RQ-04 | 顧客KYCは必要か | 条件付き要否 + 閾値 | 外部承認が必要 |
| RQ-05 | AML/CFT監視で最低限必要な体制は何か | 実務要件一覧 | 外部承認が必要 |
| RQ-06 | トラベルルール対応要否はどうか | 要/不要 + 条件 | 外部承認が必要 |
| RQ-07 | 返金における法的責任主体は誰か | 主体 + 免責条件 | 外部承認が必要 |
| RQ-08 | 誤送金・期限後着金の規約表現は何か | 条項案 | 外部承認が必要 |
| RQ-09 | 保存すべき監査ログと保存年限は何か | 項目 + 期間 | 外部承認が必要 |
| RQ-10 | 本番Go判定に必要な法務承認条件は何か | チェックリスト | 外部承認が必要 |

## 回答記録テンプレート
- 回答日:
- 回答者:
- 参考法令/文書URL:
- 結論:
- 残課題:

## Done when
- RQ-01〜RQ-10 に回答が入り、外部承認項目がゼロまたは明示管理される。

## Validation
- 回答に根拠URLまたは契約文書参照がある。
- `docs/open-questions.md` の関連項目へ反映される。

## Failure handling
- 重大項目（RQ-01,02,07）が未回答の場合は Phase 2以降を `BLOCKED` とする。
