# JPYC 公開案内Site 実装ブリーフ

Goal:

店舗端末でJPYC支払いを行う利用者へ、誤送金防止、対応チェーン・トークン、非カストディ境界、規約・プライバシー・返金方針を、決済実行機能なしで明確に案内する。

Context:

実際の請求作成、送金先、金額、QR、入金監視、審査、返金証跡、精算、監査はMacの店舗端末が担う。Siteは一般公開の静的案内だけを担い、OpenAI Sites上で金融取引を開始・実行・促進しない。

Target users:

- 店頭で初めてJPYCを使う利用者
- 支払い前に安全条件を確認する利用者
- 返金・プライバシー・問い合わせ方針を確認する利用者
- 店舗スタッフと管理者が案内先として提示する利用者

Primary flow:

1. 最上部の警告で「店舗端末のQRからのみ」「このSiteから送金しない」を確認する。
2. Polygon、JPYC、誤送金防止、秘密鍵を共有しないことを確認する。
3. 支払いガイドまたは各ポリシーを読む。
4. 実際の支払いは店舗端末へ戻り、ウォレットで店舗端末のQRを読み取る。

States to support:

- 通常案内
- 支払い前の注意
- 誤チェーン・誤トークン・誤アドレス警告
- 返金は自動ではなく審査・承認が必要という状態
- 問い合わせ時に秘密鍵・シードフレーズを送らない案内
- 法務・運営者情報の外部承認が未検証の場合は、本番GOへ昇格しない

Existing UI patterns to reuse:

- `public/app.css` の青、緑、黄、赤、ニュートラルの運用色
- 44px以上のタップ領域
- 高コントラストのカード、警告、バッジ、明確な見出し
- 色だけに依存しない状態ラベル

Constraints:

- 金額、受取アドレス、動的QR、EIP-681、ウォレットリンク、支払いボタン、顧客データ、tx hash入力、D1、R2、Secretsを置かない。
- プロフィールや過去会話から個人名、住所、電話番号、個人メールを補完しない。
- 返金の自動実行、資産保管、秘密鍵管理を示唆しない。
- 3〜5色、モバイル優先、水平スクロールなし、200%拡大、キーボード操作、スクリーンリーダーの基本導線を満たす。

Implementation notes:

- 日本語のシステムフォントを使用し、外部フォントを読み込まない。
- 全ページ共通の警告帯、ヘッダー、フッター、文書メタデータを使う。
- ナビゲーションは狭い幅で折り返し、主要リンクを常に到達可能にする。
- 公開情報Site自体はフォーム・ログイン・永続状態を持たない。

Validation plan:

- build、lint、リンク・禁止語・Secretsの静的検査。
- 393px（Pixel 9a相当）、390px（iPhone 12相当）、1280px、200%拡大で表示確認。
- キーボードフォーカス、見出し順、ランドマーク、コントラスト、水平overflowを確認。
- `/terms`、`/privacy`、`/refund-policy` を含む全9ルートの200応答を確認。

Failure handling:

法務承認、公開運営者情報、問い合わせ先の直接証拠がない場合、情報を捏造せず、本番GOをブロックする。安全なSite実装・private preview・技術検証は継続する。
